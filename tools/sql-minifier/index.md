# Минификатор SQL онлайн

Сократите размер SQL-запросов, удалив лишние пробелы, переносы строк и комментарии. Получите компактный SQL-код с сохранением строковых значений и синтаксически значимых конструкций выбранного диалекта.

Важно

Минификация изменяет только текстовое представление SQL-запроса, но не выполняет его и не подключается к базе данных.

Даже если размер запроса уменьшился, это не гарантирует его успешное выполнение. Минификатор не проверяет существование таблиц и столбцов, правильность бизнес-логики и результат выполнения запроса.

Сохраняйте исходную версию запроса: после удаления комментариев восстановить их из результата нельзя.

## Что такое минификация SQL?

Минификация SQL - это процесс сокращения текстового представления SQL-запроса за счёт удаления лишних пробелов, переносов строк, отступов и обычных комментариев. В результате получается компактный код, который занимает меньше места, но сохраняет структуру и смысл исходного запроса при корректной обработке синтаксиса выбранного диалекта.

Минифицированный SQL удобен, когда запросы нужно передавать внутри приложений, хранить в конфигурационных файлах, записывать в журналы или использовать в других местах, где важен размер текстовых данных.

## Как работает минификатор SQL?

Инструмент анализирует SQL-код посимвольно и определяет, какие части относятся к синтаксису, строковым значениям, идентификаторам и комментариям. Это позволяет удалять лишние символы, не затрагивая содержимое строк и другие конструкции, для которых пробелы и специальные символы имеют значение.

В отличие от простой замены пробелов регулярными выражениями, лексический анализатор учитывает контекст. Например, последовательность `--` внутри строкового значения не должна восприниматься как начало комментария.

При включённой настройке удаления комментариев обычные комментарии исключаются из результата. Специальные комментарии, содержащие инструкции для СУБД или подсказки оптимизатору, сохраняются.

## Зачем минифицировать SQL-запросы?

Минификация помогает сделать текстовое представление запроса компактнее и удобнее для передачи между компонентами системы.

### Уменьшение размера текста

Удаление лишних пробелов и комментариев уменьшает размер SQL-строки. Это удобно при передаче запросов между компонентами приложения и хранении SQL в текстовых файлах и конфигурациях.

### Компактные журналы

Минифицированные запросы занимают меньше места в журналах и технических записях. Это помогает уменьшить объём текстовых данных, особенно если приложение генерирует большое количество SQL-запросов.

### SQL внутри приложений

Компактный SQL удобнее помещать в конфигурации, шаблоны и программный код, где длинные многострочные запросы могут усложнять структуру файлов.

## Что важно учитывать при минификации SQL?

Минификация изменяет текстовое представление запроса, но не является оптимизацией SQL на уровне базы данных. Удаление пробелов само по себе не делает выполнение запроса быстрее и не изменяет план выполнения.

Не удаляйте исходные версии запросов. После минификации код становится значительно сложнее читать и отлаживать. Если комментарии были удалены, восстановить их из минифицированного результата невозможно.

Перед использованием результата в рабочем окружении проверьте его на целевой СУБД, особенно если запрос содержит нестандартные конструкции или особенности конкретного диалекта.

## Минификация SQL и оптимизация SQL: в чём разница?

Минификация уменьшает количество символов в текстовом представлении запроса. Она работает с пробелами, переносами строк и комментариями.

Оптимизация SQL направлена на повышение эффективности выполнения запроса. Она может включать изменение структуры JOIN, выбор индексов, анализ плана выполнения, сокращение объёма обрабатываемых данных и устранение неэффективных операций.

Это разные задачи. Минифицированный запрос не обязательно выполняется быстрее исходного. Если ваша цель - улучшить производительность базы данных, используйте инструменты анализа SQL и планы выполнения запросов.

## Поддерживаемые диалекты SQL

Правила обработки комментариев, строк и идентификаторов различаются между СУБД. Выберите диалект, для которого написан запрос.

В минификаторе реализованы правила для диалектов, перечисленных ниже. Другие диалекты в интерфейсе не доступны для выбора.

| Диалект | Особенности лексики |
| --- | --- |
| MySQL | Обратные кавычки, #-комментарии, -- только перед пробелом, исполняемые комментарии /*! … */ |
| PostgreSQL | Двойные кавычки, долларовые строки, вложенные блочные комментарии, escape-строки E'…' |
| SQLite | Компактный диалект: двойные кавычки и обычные комментарии -- и /* … */ |
| MariaDB | Правила MySQL и исполняемые комментарии /*M! … */ |
| SQL Server | Квадратные скобки, строки N'…', разделитель пакетов GO, вложенные комментарии |

## Часто задаваемые вопросы

- **Меняет ли минификация результат выполнения SQL-запроса?:** При корректной обработке синтаксиса выбранного диалекта минификация должна сохранять смысл запроса. Инструмент удаляет только избыточное форматирование и выбранные обычные комментарии. Содержимое строковых значений и значимых конструкций SQL сохраняется. Тем не менее перед использованием важного запроса в production-среде рекомендуется проверить результат на целевой СУБД.
- **Удаляются ли все SQL-комментарии?:** При включённой настройке удаляются обычные однострочные и многострочные комментарии. Комментарии, содержащие подсказки оптимизатору или исполняемые конструкции конкретной СУБД, сохраняются. Это необходимо для предотвращения изменения поведения запроса.
- **Поддерживаются ли разные SQL-диалекты?:** Минификатор учитывает особенности выбранного диалекта SQL, включая правила обработки комментариев, строк и идентификаторов. Выберите соответствующую СУБД перед обработкой запроса. Поддержка распространяется на диалекты, реализованные в инструменте.
- **Станет ли запрос выполняться быстрее?:** Нет. Минификация сама по себе не ускоряет выполнение SQL на стороне СУБД и не оптимизирует план запроса. Основная задача инструмента - уменьшение размера текстового представления SQL-кода.
- **Сохраняются ли пробелы внутри строк?:** Да. Пробелы и другие символы внутри строковых значений сохраняются. Например, значение `'Hello World'` не превращается в `'HelloWorld'`. Маркеры комментариев внутри строк также не обрабатываются как настоящие комментарии.
- **Отправляется ли мой SQL на сервер?:** Нет. Минификация выполняется непосредственно в вашем браузере. SQL-код не отправляется на сервер и не сохраняется в базе данных приложения.
- **Можно ли вернуть исходное форматирование?:** Для восстановления структуры и отступов можно использовать SQL Formatter. Однако если комментарии были удалены, восстановить их из минифицированного результата нельзя. Поэтому всегда сохраняйте исходную версию запроса.
- **Проверяет ли минификатор правильность SQL?:** Нет. Инструмент отвечает за сокращение текстового представления SQL, а не за полную проверку грамматики, существование таблиц или корректность логики запроса. Для проверки синтаксиса используйте SQL Syntax Validator.
- **Можно ли минифицировать несколько SQL-запросов одновременно?:** Да. Вы можете вставить несколько SQL-операторов в одно поле. Минификатор сохранит разделители операторов и необходимые границы команд, учитывая особенности выбранного диалекта и используемых клиентских инструментов.
