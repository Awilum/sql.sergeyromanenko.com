Преобразуйте регулярные выражения в SQL LIKE. Получите SQL-условие для поиска по началу строки, окончанию строки или произвольному фрагменту текста. Инструмент анализирует шаблон и показывает, какие конструкции можно точно выразить через LIKE, а какие требуют полноценной поддержки регулярных выражений.

SQL LIKE поддерживает только ограниченный набор возможностей регулярных выражений. Простые шаблоны с обычными символами, якорями ^ и $ и конструкциями . и .* можно преобразовать в LIKE. Символьные классы, группы альтернатив и большинство квантификаторов не имеют прямого эквивалента.

Инструмент не пытается приблизительно переписывать неподдерживаемые выражения. Если точное преобразование невозможно, вы получите объяснение причины, а не потенциально некорректное SQL-условие.

Результат не выполняется в базе данных. Учитывайте особенности выбранной СУБД, правила сравнения строк, сортировку и чувствительность к регистру. Перед использованием проверьте полученное условие на целевой базе данных.

## Что такое Regex to LIKE?

Regex to LIKE - это преобразование простых регулярных выражений в шаблоны SQL LIKE. Оно позволяет заменить некоторые регулярные выражения более простыми условиями поиска по строковым значениям в базе данных.

Регулярные выражения предоставляют широкие возможности поиска: символьные классы, группы, альтернативы, квантификаторы и другие конструкции. SQL LIKE работает проще: он использует символ процента для обозначения произвольной последовательности символов и подчёркивание для обозначения одного символа.

Именно поэтому не каждое регулярное выражение можно преобразовать в LIKE. Инструмент распознаёт поддерживаемые конструкции и сообщает, когда для сохранения исходной логики необходим полноценный regex-механизм.

## Как работает преобразование Regex в SQL LIKE?

Инструмент анализирует регулярное выражение посимвольно. Он определяет якоря начала и конца строки, обычные символы, экранированные метасимволы и конструкции, описывающие произвольные символы.

Якорь ^ указывает на начало строки, а $ - на её конец. Конструкция .* соответствует произвольной последовательности символов и преобразуется в %. Отдельная точка . преобразуется в _, который обозначает один символ в SQL LIKE.

Если выражение не содержит якорей, инструмент рассматривает его как поиск фрагмента внутри строки и добавляет необходимые подстановочные знаки по краям шаблона.

Перед генерацией SQL инструмент проверяет, можно ли сохранить смысл исходного выражения. Если обнаружены символьные классы, альтернативы, квантификаторы или другие неподдерживаемые конструкции, преобразование блокируется и пользователь получает объяснение.

## Какие конструкции Regex поддерживает SQL LIKE?

Следующие конструкции можно преобразовать в SQL LIKE в рамках ограничений, описанных в этом инструменте.

| Регулярное выражение | Значение | SQL LIKE |
| --- | --- | --- |
| `^заказ` | Строка начинается с заказ | `заказ%` |
| `заказ$` | Строка заканчивается на заказ | `%заказ` |
| `^заказ$` | Точное совпадение | `заказ` |
| `заказ` | Поиск фрагмента | `%заказ%` |
| `.*` | Любая последовательность символов | `%` |
| `.` | Один произвольный символ | `_` |
| `\.` | Буквальная точка | `.` |
| `\+` | Буквальный плюс | `+` |

Необходимо учитывать, что соответствие отдельных символов не гарантирует полной эквивалентности всех regex-движков и SQL-сопоставлений. В частности, поведение точки и проверка регистра зависят от контекста и реализации СУБД.

## Какие регулярные выражения нельзя преобразовать в SQL LIKE?

SQL LIKE не является полноценной заменой регулярным выражениям. Символьные классы, повторения, альтернативы и сложные группы не имеют общего прямого эквивалента в стандартном шаблоне LIKE.

| Конструкция | Пример | Причина |
| --- | --- | --- |
| Символьный класс | `[а-яё]` | Выбор символа из диапазона |
| Диапазон цифр | `[0-9]` | Проверка принадлежности классу |
| Повторение | `заказ+` | Один или несколько символов |
| Необязательный символ | `заказ?` | Ноль или одно повторение |
| Количество повторений | `заказ{3}` | Фиксированное число повторений |
| Альтернатива | `(кот\|пёс)` | Несколько вариантов совпадения |
| Цифровой класс | `\d` | Специальный класс символов |
| Группы просмотра | `(?=...)` | Lookahead или lookbehind |

Если регулярное выражение использует подобные конструкции, используйте нативные возможности регулярных выражений соответствующей СУБД, когда они доступны. Не заменяйте сложное условие приблизительным LIKE, если от результата зависит корректность выборки.

## Особенности SQL LIKE в разных СУБД

Оператор LIKE присутствует в поддерживаемых диалектах, но детали обработки строк, экранирования и сравнения значений могут различаться. Выбирайте ту СУБД, в которой планируете выполнять полученное условие.

| Диалект | Оператор | Особенности |
| --- | --- | --- |
| PostgreSQL | `LIKE` | Сравнение с учётом регистра; также существует отдельный оператор ILIKE |
| MySQL | `LIKE` | Чувствительность к регистру зависит от collation и режима сравнения |
| SQLite | `LIKE` | По умолчанию регистронезависим для ASCII; для Unicode поведение отличается |
| MariaDB | `LIKE` | Поведение зависит от collation и настроек сравнения |
| SQL Server | `LIKE` | Результат сравнения зависит от collation |

Кодировка базы данных и настройки collation влияют на сравнение кириллических значений: один и тот же шаблон может дать разные результаты в разных СУБД. Инструмент формирует условие LIKE и не пытается самостоятельно изменять правила сравнения строк. Если требуется определённая чувствительность к регистру, проверьте настройки collation или используйте подходящий механизм сравнения в вашей СУБД.

## Почему важно экранировать символы % и _ в SQL LIKE?

Символы % и _ имеют специальное значение в SQL LIKE. Первый обозначает любое количество символов, а второй - ровно один символ. Поэтому буквальное значение этих символов нужно экранировать.

Например, регулярное выражение ^файл_.* содержит обычное подчёркивание. Если просто преобразовать его в файл_%, SQL начнёт воспринимать подчёркивание как шаблон одного произвольного символа.

Инструмент использует отдельный escape-символ !. Поэтому корректный результат выглядит так:

```sql
WHERE имя_файла LIKE 'файл!_%' ESCAPE '!'
```

Такой подход сохраняет различие между литеральными символами исходного регулярного выражения и специальными подстановочными знаками SQL LIKE.

## SQL LIKE и регулярные выражения: в чём разница?

SQL LIKE предназначен для простого сопоставления строковых значений. Он позволяет искать точные значения, префиксы, суффиксы и фрагменты текста с помощью двух основных подстановочных знаков.

Регулярные выражения значительно выразительнее. С их помощью можно проверять диапазоны символов, повторения, группы, альтернативы, границы слов и многие другие условия.

Поэтому преобразование Regex в LIKE полезно только тогда, когда исходный шаблон действительно укладывается в возможности SQL LIKE. Для сложных выражений следует использовать regex-поддержку соответствующей СУБД, а не пытаться искусственно упростить выражение.

## Часто задаваемые вопросы

- **Можно ли преобразовать любое регулярное выражение в SQL LIKE?:** Нет. SQL LIKE поддерживает только ограниченный набор шаблонов. Простые выражения с якорями, обычными символами и конструкциями . и .* можно преобразовать. Символьные классы, группы альтернатив и большинство квантификаторов не имеют прямого эквивалента.
- **Чем отличаются % и _ в SQL LIKE?:** Символ % соответствует последовательности из нуля или более символов. Символ _ соответствует ровно одному символу. Если эти символы должны восприниматься буквально, необходимо использовать механизм ESCAPE.
- **Что означает ^ в регулярном выражении?:** Символ ^ обозначает начало строки. Например, ^администратор соответствует строкам, начинающимся с «администратор». При преобразовании это условие превращается в LIKE 'администратор%'.
- **Что означает $ в регулярном выражении?:** Символ $ обозначает конец строки. Например, администратор$ соответствует строкам, заканчивающимся на «администратор». При преобразовании это условие превращается в LIKE '%администратор'.
- **Что означает .* в SQL LIKE?:** Конструкция .* в регулярном выражении обозначает произвольное количество символов и преобразуется в символ % в SQL LIKE. Например, ^пользователь.* превращается в LIKE 'пользователь%'.
- **Почему некоторые регулярные выражения не преобразуются?:** Потому что SQL LIKE не поддерживает все возможности регулярных выражений. Например, выражение [0-9]+ содержит символьный класс и квантификатор. Для такого поиска необходим полноценный механизм регулярных выражений.
- **Учитывает ли инструмент регистр символов?:** Инструмент генерирует обычный оператор LIKE. Чувствительность к регистру зависит от выбранной СУБД, collation и настроек сравнения строк. Сам инструмент не меняет правила сравнения.
- **Выполняется ли SQL-запрос в базе данных?:** Нет. Инструмент только анализирует регулярное выражение и генерирует текстовое SQL-условие. Он не подключается к базе данных, не выполняет запросы и не проверяет существование таблиц или столбцов.
- **Отправляется ли регулярное выражение на сервер?:** Нет. Анализ и преобразование выполняются непосредственно в браузере. Введённый шаблон не отправляется на сервер и не сохраняется в базе данных приложения.
- **Можно ли использовать результат напрямую в запросе?:** Полученное условие можно использовать как часть SQL-запроса после проверки. Имя столбца указывается в инструменте до преобразования и сразу включается в результат: вручную редактировать SQL для этой цели не нужно. Проверьте экранирование и убедитесь, что поведение LIKE соответствует требованиям вашей СУБД.
